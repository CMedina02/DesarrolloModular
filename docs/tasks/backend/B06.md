# B06 · Activación de módulos por empresa

## 1. Objetivo

Registrar los módulos disponibles, consultar su configuración por empresa y permitir que el administrador de plataforma habilite o deshabilite Inventario conservando sus datos.

## 3. Funcionamiento técnico

Aplica la migración una vez a una base que ya tenga el esquema T02. Para la instalación local documentada, el comando desde la raíz del repositorio es:

```bash
psql -X -v ON_ERROR_STOP=1 -h 127.0.0.1 -U inventario_app -d inventario_comercial \
  -f backend/database/migrations/004_business_modules.sql
```

El único módulo registrado en el MVP es `inventory`. Su estado inicial es deshabilitado para cada empresa, tanto para empresas existentes como nuevas. La API muestra ese estado aunque todavía no exista una fila de configuración.

| Operación bajo `/api/v1` | Acceso y respuesta |
| --- | --- |
| `GET /businesses/{business_id}/modules` | Devuelve `[{"key":"inventory","enabled":false}]` cuando Inventario está deshabilitado. `ADMIN` y `EMPLOYEE` consultan su propia empresa. `PLATFORM_ADMIN` consulta las empresas de la instalación. |
| `PUT /businesses/{business_id}/modules/inventory` | `PLATFORM_ADMIN` envía `{"enabled":true}` o `{"enabled":false}`. Recibe el objeto con el estado guardado. Puede preparar también una empresa inactiva. |

Al entrar a `/api/v1/businesses/{business_id}/inventory`, Express verifica el JWT, el rol, el ámbito de empresa y el estado de Inventario. Un usuario con alcance válido recibe `403` si el módulo está deshabilitado. Las rutas de categorías y productos se incorporarán en B07 y B08. Mientras se implementan, una solicitud que supera el control de acceso llega a la respuesta general `404`.

## 4. Decisiones de diseño

- El catálogo forma parte del código de la aplicación. La base almacena el estado por empresa de los módulos registrados. La desactivación modifica únicamente esa configuración.
- La llave primaria `(business_id, module_key)` y `INSERT … ON CONFLICT DO UPDATE` permiten repetir la misma solicitud o ejecutarla en paralelo sin duplicar registros. [Documentación de PostgreSQL sobre INSERT](https://www.postgresql.org/docs/18/sql-insert.html).
- El cambio de estado reutiliza la autorización transaccional de B05. El acceso a Inventario se comprueba en el servidor, aunque Flutter muestre u oculte pantallas según el estado.

## 5. Pruebas

`npm test` desde `backend/` pasó 29 pruebas. Los casos de B06 verifican lectura por empresa, permisos de escritura, validación del booleano y orden de los controles antes de acceder a Inventario.

En PostgreSQL temporal se aplicó la migración a una base con empresas, catálogo, existencias y un movimiento de T02. La prueba verificó el estado inicial, la independencia entre empresas, dos habilitaciones simultáneas y el bloqueo HTTP al desactivar Inventario. Al desactivar y reactivar el módulo se conservaron la categoría, el saldo y el movimiento.

`redocly lint --extends minimal docs/api/openapi.yaml` validó el contrato desde la raíz del repositorio.

## 6. Explicación para el profesor

> Inventario es un módulo incluido en el backend. Cada empresa tiene su propio estado de habilitación y solo el administrador de plataforma puede cambiarlo. Express comprueba ese estado antes de entrar al módulo. Las pruebas demuestran que el cambio solo afecta el acceso y que se conservan los productos, las existencias y el historial.
