# B07 · Categorías de Inventario

## 1. Objetivo

Organizar el catálogo por categorías y permitir que cada empresa las consulte y administre dentro de su propio Inventario.

## 2. Implementación

| Archivo | Contenido |
| --- | --- |
| `backend/src/modules/inventory/categories/routes.js` y `repository.js` | Rutas, validación y consultas de categorías por empresa. |
| `backend/src/core/modules/access.js` y `repository.js` | Revisión de la habilitación del módulo dentro de la transacción de escritura. |
| `backend/src/core/http/pagination.js` y `backend/src/core/businesses/` | Paginación compartida con las rutas de administración. |
| `backend/src/core/security/write-response.js`, `backend/src/app.js` y `server.js` | Respuesta de eliminación, registro de rutas y conexión al pool de PostgreSQL. |
| `backend/test/app.test.js` y [OpenAPI](../../api/openapi.yaml) | Pruebas HTTP y contrato de categorías. |

## 3. Funcionamiento técnico

Las rutas requieren una sesión activa y que Inventario esté habilitado para la empresa, según [B06](B06.md). `ADMIN` y `EMPLOYEE` pueden consultar. Las escrituras requieren `ADMIN`. La empresa autorizada se toma de la sesión y debe coincidir con la ruta.

| Operación bajo `/api/v1/businesses/{business_id}/inventory` | Resultado |
| --- | --- |
| `GET /categories` | `200` con `items`, `limit` y `offset`. Ordena por UUID y usa 25 registros por defecto, con máximo de 100. |
| `POST /categories` | `201` con la categoría creada. |
| `GET /categories/{category_id}` | `200` con la categoría de la empresa. |
| `PATCH /categories/{category_id}` | `200` con el nuevo nombre y la fecha de actualización. |
| `DELETE /categories/{category_id}` | `204` sin cuerpo si la categoría carece de productos asociados. |

El alta y la edición reciben `{"name":"Herramientas"}` como JSON. El servidor recorta espacios exteriores y valida un nombre de 1 a 100 caracteres. Un UUID inválido devuelve `400`. Una categoría ajena o inexistente devuelve `404`. El nombre duplicado sin distinguir mayúsculas y la eliminación de una categoría usada por un producto devuelven `409`, incluso si el producto está inactivo.

## 4. Decisiones de diseño

- Cada consulta filtra por empresa. Las operaciones sobre una categoría concreta filtran además por su UUID.
- PostgreSQL hace cumplir la unicidad del nombre por empresa mediante el índice de T02 y conserva las referencias mediante la llave foránea de productos. El respaldo de la base cubre escrituras concurrentes. PostgreSQL 18 reportó el borrado de una categoría referenciada con SQLSTATE `23001`. La API traduce ese código y `23503` a `409` para esa restricción.
- El control inicial de Inventario protege las consultas. En las escrituras la transacción de B05 vuelve a revisar cuenta y empresa. Después verifica y bloquea con `FOR SHARE` el estado de Inventario hasta confirmar la mutación. Una desactivación concurrente que se confirma primero impide la escritura. [Aislamiento Read Committed de PostgreSQL](https://www.postgresql.org/docs/18/transaction-iso.html).
- El CRUD usa el esquema existente y la migración de módulos de B06.

## 5. Pruebas

Desde `backend/`, `npm test` pasó 33 pruebas. Los casos de B07 verifican lectura por empresa, permisos de escritura, paginación, validación del nombre, respuestas `409`, eliminación sin cuerpo y rechazo de una escritura al desactivar el módulo. Desde la raíz, `redocly lint --extends minimal docs/api/openapi.yaml` validó el contrato.

En PostgreSQL temporal se ejecutó el CRUD con dos empresas. Se confirmó que el mismo nombre puede existir en ambas, que cada empresa queda aislada y que las categorías con productos activos o inactivos siguen protegidas. Se mantuvo abierta una transacción de desactivación mientras llegaba una edición. Al confirmar la desactivación, la API respondió `403` y el nombre de la categoría se conservó.

## 6. Explicación para el profesor

> El módulo Inventario ya permite listar, crear, renombrar y eliminar categorías. Express verifica el rol y la empresa del usuario, y cada consulta SQL usa ese ámbito. PostgreSQL impide nombres duplicados dentro de una empresa y protege categorías que todavía tienen productos. Probamos esos controles con dos empresas y confirmamos que desactivar el módulo bloquea las escrituras.
