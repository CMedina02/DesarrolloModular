# B11 · Pruebas integrales del backend

## 1. Objetivo

Validar de forma reproducible el flujo real de Inventario desde HTTP hasta PostgreSQL. La suite cubre autorización, aislamiento por empresa, saldo, concurrencia y reversión de transacciones.

## 2. Implementación

| Archivo | Contenido |
| --- | --- |
| `backend/integration/harness.js` | Crea el esquema de pruebas, aplica T02 y B06, provisiona el primer administrador y arranca Express en un puerto temporal. |
| `backend/integration/inventory.integration.js` | Ejecuta los cinco escenarios de integración con dos empresas y tres roles. |
| `backend/src/backend-app.js` y `backend/src/server.js` | Comparten la configuración real de Express, los repositorios, la autenticación y el pool entre el arranque normal y la suite. |
| `backend/package.json` y [README](../../../README.md) | Comando de integración e instrucciones de reproducción. |

## 3. Funcionamiento técnico

Usa una base PostgreSQL de pruebas con permisos para crear esquemas. La suite lee `INTEGRATION_DATABASE_URL` del entorno y crea un esquema temporal con un identificador aleatorio. Antes de aplicar los archivos SQL verifica que ese esquema sea el actual. Al terminar, cierra Express y el pool y retira el esquema que creó. PostgreSQL usa `search_path` para resolver los objetos cuyo nombre carece de un esquema explícito. [Esquemas en PostgreSQL](https://www.postgresql.org/docs/18/ddl-schemas.html)

Desde `backend/`, instala con `npm ci`. En Bash puedes introducir la URL de pruebas con una entrada oculta:

```bash
read -rs -p 'URL de PostgreSQL de pruebas: ' INTEGRATION_DATABASE_URL
printf '\n'
export INTEGRATION_DATABASE_URL
npm run test:integration
unset INTEGRATION_DATABASE_URL
```

En PowerShell 7.3 o posterior:

```powershell
$env:INTEGRATION_DATABASE_URL = Read-Host -MaskInput -Prompt 'URL de PostgreSQL de pruebas'
npm run test:integration
Remove-Item Env:INTEGRATION_DATABASE_URL
```

## 4. Decisiones de diseño

- La suite de integración usa el mismo ensamblado de Express y PostgreSQL que el servidor normal. Las pruebas rápidas con dobles se ejecutan con `npm test`.
- La inicialización crea usuarios y credenciales temporales. Las empresas, sus cuentas y el catálogo se levantan mediante la API.
- El escenario de reversión instala un disparador de prueba solo dentro del esquema aislado. La consola muestra deliberadamente un error HTTP interno cuando ese disparador impide guardar un movimiento.

## 5. Pruebas

| Escenario | Resultado observado |
| --- | --- |
| Inicio de sesión y flujo de catálogo y stock | El producto inició en cero. Entrada, salida y ajuste dejaron `1.500` y tres movimientos con los saldos esperados. |
| Roles, empresas y módulos | Se rechazaron las operaciones fuera de alcance. Desactivar una empresa para Inventario bloqueó su lectura y escritura. Reactivar el módulo conservó sus datos y la otra empresa siguió operando. |
| Dos salidas concurrentes | Una devolvió `201` y la otra `409`. Quedaron `0.400` y una sola salida en el historial. |
| Reversión al fallar el historial | El saldo y el historial se conservaron. PostgreSQL rechazó borrar el movimiento existente. |
| Revocación durante una escritura | La solicitud esperó el cambio de rol, devolvió `403` y dejó intacto el producto. |

Se ejecutó `npm test` con Node.js 26.13.1 y pasaron las 42 pruebas existentes. `npm run test:integration` pasó dos veces contra PostgreSQL 18.7 temporal. El ejecutor contabilizó seis pruebas por ejecución, incluido el caso padre. Tras ambas ejecuciones se verificó que se retiró el esquema de pruebas y que una tabla de control externa conservó su registro.

## 6. Explicación para el profesor

> Levantamos el backend real con una base aislada y lo probamos por HTTP con los tres roles. Demostramos que dos empresas mantienen inventarios separados, que una salida concurrente queda rechazada si el saldo ya no alcanza y que un fallo al guardar el historial revierte el stock. La suite puede repetirse con el mismo comando sobre PostgreSQL de pruebas.

## 7. Instalación y alcance

El comando de integración comparte el migrador y ejecuta los casos de B11 y B12. [Instalación y migraciones](B12.md)
